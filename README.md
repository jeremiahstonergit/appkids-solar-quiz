# AppKids: Солнечная система

Адаптивный мобильный web-прототип детской викторины для детей 4–7 лет.

## Возможности

- 12 вопросов и 6 игровых механик;
- крупные touch-зоны и интерфейс без hover-зависимых действий;
- адаптация для телефонов и iPad в portrait/landscape;
- контентные изображения из публичного S3;
- без backend, аккаунтов и таймера.

## Локальный запуск

Для разработки и тестов используется Node.js 24.15+ (ветка 24 LTS).

```bash
npm install
npm run dev
```

## Сборка и production-запуск

```bash
npm run build
npm start
```

`npm start` раздаёт папку `dist` на `0.0.0.0:8080`.

SpaceWeb: тип проекта — Node.js, корневая директория — корень репозитория.

## Офлайн-сборка для будущего Android-приложения

Только основная версия. Android-оболочка находится в `android/`.

```bash
npm ci
npm run assets:prepare
npm run build:offline
```

`assets:prepare` — отдельный подготовительный шаг с сетью: получает изображения,
203 MP3 и шрифт Manrope с лицензией OFL. Все 266 файлов проверяются по SHA-256
из `offline-assets.lock.json`. Можно вместо скачивания распаковать готовый комплект
`offline-public/` в корень проекта. Ресурсы не хранятся в Git.

`build:offline` ничего не скачивает и прерывается при отсутствии или изменении
любого ресурса. Результат — `dist-offline/`: локальные изображения, звук, шрифты,
код и вопросы. CSP запрещает внешние ресурсы и сетевые подключения. Проверка
сборки контролирует контрольные суммы, ссылки и отсутствие S3/Google Fonts.
Проверка на реальном Android с отключённой сетью будет отдельным этапом.

Обычный `npm run build` по-прежнему создаёт веб-версию `dist/` с S3.
Офлайн-изменения не переносить в `debug/all-questions`.

## Пробная Android APK

Используется Capacitor 8.5.2. Для сборки нужны JDK 21 и Android SDK 36
(устанавливаются вместе с актуальным Android Studio). Минимальная версия
устройства — Android 7.0/API 24; совместимость проверяется отдельно на устройстве.

```bash
npm ci
npm run assets:prepare
npm run android:sync
npm run android:open
```

В Android Studio: Build → Generate App Bundles or APKs → Generate APKs.
Либо из терминала Linux/macOS: `npm run android:debug`.
На Windows после `npm run android:sync`: `cd android`, затем
`.\gradlew.bat :app:assembleDebug`.

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`.
Это установочная отладочная APK, не релиз для магазина. Ключ релизной подписи
пока не создаётся; временные ключи не коммитятся. Иконка и заставка пока шаблонные.

`npm run android:verify` (Linux/macOS, `unzip` и `ANDROID_HOME`) проверяет
подпись готовой APK, отсутствие сетевых разрешений и хеши всех 266 ресурсов
непосредственно внутри APK.

Сборка встраивает все ресурсы и проверяет их хеши после `cap sync`. В приложении
нет удалённого сервера; разрешение INTERNET удаляется при слиянии манифестов,
сетевые загрузки WebView заблокированы, резервное копирование выключено.
Адрес `https://localhost` — внутренний адрес встроенных файлов, не сетевой сервер.
Загрузка SDK/зависимостей нужна при сборке, но не при запуске установленной игры.

После подключения устройства: `cd android && ./gradlew :app:connectedDebugAndroidTest`
проверяет отсутствие разрешения INTERNET и наличие всех групп озвучки.
Первый запуск в авиарежиме, звук, повороты, сворачивание и кнопка «Назад» требуют
отдельной проверки; прохождение JS-тестов её не заменяет.

## Источник контента

- Единственный источник истины для формулировок, вариантов, правильных ответов, сложности, возраста и объяснений — лист `Солнечная система вопросы` в рабочей таблице вопросов.
- После изменения листа вопросов нужно проверить и при необходимости обновить листы `Солнечная система объекты` и `Проверка ассетов`.
- Затем одинаковые данные вопросов, объектов и сложности синхронизируются в `main` и `debug/all-questions`. Различаться между ветками должен только режим прохождения/отладки.
- Перед коммитом обязательны `npm test` и `npm run build` в обеих ветках.

## Регрессионные проверки

`npm test` проверяет данные, аудиоплеер, рендер всех 78 вопросов и прохождение всех механик через DOM-контролы. Звук и время моделируются: тесты не подтверждают качество реальных записей или совместимость с Android WebView.

Покрыты порядок озвучки, подсветка только во время воспроизведения, прерывание/выключение звука, переходы экранов, четыре раунда сортировки, ранжирование с повторными попытками, таймеры и загрузка изображений из кеша. CI запускает тесты и сборку для `main` и `debug/all-questions`.

Озвучка «Правда» и «Ложь» пока не включена: этих двух файлов нет в комплекте из 203 записей. При ошибочном ответе на истинное утверждение повторяется запись самого верного утверждения; для отдельной поддерживающей реакции без объяснения нужна новая запись. Несуществующие MP3 не запрашиваются.
